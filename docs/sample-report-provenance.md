# Sample report provenance

`site/reports/good.json` and `bad.json` are the original v0.1.0 synthetic notes browser captures from audited source commit `a74a81c9c4c6ffc0a3246bf1764f6d508343df0e`. Their original run IDs, capture/finish timestamps, environment and stored provenance have not been changed.

| Retained capture | SHA-256 |
| --- | --- |
| `good.json` | `c6aed939a527c45592241d0423cf210d60b4276eb206af91455335d23e320457` |
| `bad.json` | `66b01198ab504f2cdc365b3fc3c153e531547c2b5c5267ad625d43a9e03d4c96` |

The corresponding HTML has been regenerated by the corrected renderer using `npm run build` followed by `npm run samples:render`. Every regenerated sample has a visible footer notice and the source JSON digest. This is formatter regeneration, not a new browser run. The script retains the capture bytes and produces deterministic HTML; it does not invent a new `sourceCommit`, run ID or timestamp.

Existing screenshots and the demo video remain original release media and are not presented as newly executed screenshots. Fresh typed-key consumer runs, offline report screenshots, machine-readable UI assertions and command logs are created separately by `npm run test:typed-keys` / `npm run test:consumer`. Those use an independently authored synthetic static application, not the notes sample and not an external real application pilot.
