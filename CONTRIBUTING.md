# Contributing

Use Node 24.21.0 and the committed lockfile. Follow README's explicit build/test commands. Test real cold-control and retained-profile good/bad paths; never weaken an expected application value to hide a failing migration, replace the lifecycle with JSON restore, skip failing tests, or bypass unsupported evidence.

Add focused tests for meaningful behavior changes. Browser expectations should come from an independent fixture specification, not the production evaluator. Use only owned isolated profiles and synthetic data; never attach ordinary Chrome profiles, production credentials or another run's resources. Keep report values escaped and read-only probes nonmutating. Describe the problem, resulting behavior and validation in contributions. Changing published code requires a new version and exact-commit release verification.

After `npm ci` and `npm run build`, run `npm run verify:schema`, `npm run test:renderer`, the existing unit/e2e suites, and `npm run test:consumer`. `npm run test:typed-keys` runs the installed-package typed-record/browser regression independently. Install Chromium explicitly with `node dist/cli/main.js install-browser --json` before browser checks. Schema parity uses draft 2020-12 and tests input before defaults; document any runtime-only rule rather than pretending the editor schema performs filesystem or cross-field checks.

Run `npm run samples:render` only to regenerate retained sample captures; its footer labels that provenance. Run `npm run verify:ui` and `npm run verify:site` when changing report/sample artifacts. `npm run benchmark:snapshots` performs bounded synthetic component measurements and retains per-repeat metrics in `artifacts/benchmarks`; do not describe its formatter fixture as a full cold run. All publication/deployment commands require separate authorization.
